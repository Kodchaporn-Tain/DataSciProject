# Traffic Analytics Prediction (ระบบพยากรณ์ปริมาณการจราจร AADT)

## 1\. แนวคิด ปัญหาที่ต้องการแก้ และประโยชน์ของแอป

- **ปัญหา:** กรมทางหลวงมีความจำเป็นต้องวางแผนงบประมาณซ่อมบำรุงทางหลวง การปรับปรุงผิวจราจร และการขยายช่องทางจราจรล่วงหน้าในแต่ละปีงบประมาณ การประเมินด้วยการคาดเดาหรือสายตาอาจทำให้การจัดสรรงบประมาณไม่สอดคล้องกับปริมาณการใช้งานจริง จนนำไปสู่ปัญหาผิวทางชำรุดทรุดโทรมและการจราจรติดขัดสะสม
- **แนวคิด:** นำประวัติข้อมูลสถิติการสำรวจปริมาณการจราจรย้อนหลังของกรมทางหลวงมาพัฒนาแบบจำลองการเรียนรู้ของ Machine Learning โดยใช้ตัวแปรเชิงเวลาร่วมกับข้อมูลสายทาง เพื่อทำนายปริมาณการจราจรเฉลี่ยรายวันต่อปี (Annual Average Daily Traffic: AADT) สำหรับปีงบประมาณในอนาคต
- **ประโยชน์:** ช่วยให้หน่วยงานภาครัฐและวิศวกรวางแผนมีข้อมูลเชิงประจักษ์ สนับสนุนการตัดสินใจ ช่วยจัดสรรงบประมาณและทรัพยากรสำหรับการบำรุงรักษาโครงข่ายทางหลวงได้อย่างแม่นยำ ตรงจุด และมีประสิทธิภาพสูงสุด

## 2\. แหล่งที่มา จำนวนข้อมูล และการแบ่งชุดฝึก/ชุดทดสอบ

- **แหล่งที่มา:** ข้อมูลประวัติการสำรวจปริมาณจราจร กรมทางหลวง (`v_aadt_2565.csv`) ผ่านเว็บไซต์ (https://data.go.th/dataset/aadt1)  
- **จำนวนข้อมูล:**  
  - ข้อมูลตั้งต้นทั้งหมด: 8,250 รายการ 
  - หลังผ่านการคัดกรองสายทางที่มีประวัติอย่างน้อย 3 ปี และสร้าง Lag Feature (ปริมาณรถปีก่อนหน้า): เหลือ 7,315 รายการ 
- **การแบ่งชุดข้อมูล (Time-Based Train-Test Split):**  
  - ชุดฝึกสอน (Train Set, ข้อมูลก่อนปีงบประมาณ 2566): 6,628 รายการ
  - ชุดทดสอบ (Test Set, ข้อมูลปีงบประมาณ 2566): 687 รายการ ใช้ข้อมูลปีล่าสุดจำลองสถานการณ์การพยากรณ์อนาคตจริง

## 3\. แบบจำลองที่ใช้ ผลประเมินหลัก และข้อจำกัด

- **แบบจำลอง:** Random Forest Regressor (ร่วมกับการทำ Log Transformation `np.log1p` เพื่อปรับความเบ้ของข้อมูลและป้องกันค่าติดลบ) 
- **ผลประเมินหลัก (Performance Metrics):**  
  - **R-squared (\$R^2\$ Score):** 0.9153 (หรือ 0.9158 บนหน้าเว็บแอป)   
  - **Mean Absolute Error (MAE):** 829.43 คัน/วัน (ประมาณ 825 คัน/วัน)  
  - **Root Mean Squared Error (RMSE):** 1,900.01 คัน/วัน  
- **ข้อจำกัด:**  
  - อาจมีความคลาดเคลื่อนในสายทางที่มีการเติบโตแบบก้าวกระโดดหรือเพิ่งตัดถนนใหม่ที่ไม่มีข้อมูลในอดีต
  - ต้องมีข้อมูลปริมาณจราจรปีก่อนหน้า (Lag Data) ของสายทางนั้นจึงจะพยากรณ์ได้อย่างสมบูรณ์

# Animal Image Classifier
## 1. แนวคิด ปัญหาที่ต้องการแก้ และประโยชน์ของแอป

- **ปัญหา:** การจำแนกสัตว์จากภาพด้วยตนเองอาจใช้เวลา และอาจไม่แน่ใจเมื่อภาพมีลักษณะหรือมุมมองที่แตกต่างกัน แอปนี้จึงช่วยให้ผู้ใช้ตรวจสอบการคาดการณ์ของระบบจากภาพได้สะดวกขึ้น อย่างไรก็ตาม ระบบรองรับเฉพาะ 3 คลาสที่กำหนดไว้ และผลลัพธ์อาจคลาดเคลื่อนตามคุณภาพของภาพและข้อมูลที่ใช้ฝึก

- **แนวคิด:** พัฒนาเว็บแอปจำแนกภาพสัตว์ด้วย Deep Learning โดยใช้โมเดล MobileNetV2 แบบ Transfer Learning ผู้ใช้สามารถอัปโหลดภาพ แล้วให้ระบบทำนายว่าเป็น นก (Bird), แมว (Cat) หรือสุนัข (Dog) พร้อมแสดงคะแนนการทำนายของแต่ละคลาส

- **ประโยชน์:** 
  - ช่วยจำแนกภาพนก แมว และสุนัขได้อย่างรวดเร็ว
  - แสดงคะแนนการทำนายของแต่ละคลาส เพื่อให้ผู้ใช้เปรียบเทียบผลได้
  - เป็นตัวอย่างการประยุกต์ใช้ Deep Learning และ Transfer Learning กับการจำแนกภาพ
  - สามารถใช้เป็นสื่อประกอบการเรียนรู้เรื่องการเตรียมข้อมูล การฝึกโมเดล และการนำโมเดลไปใช้งานผ่านเว็บแอป

## 2. แหล่งที่มา จำนวนข้อมูล และการแบ่งชุดฝึก/ชุดทดสอบ

### แหล่งที่มาของข้อมูล

โค้ดกำหนดให้อ่านภาพจากโฟลเดอร์ภายในโปรเจกต์ ได้แก่

-   `train_images/` --- ชุดข้อมูลสำหรับฝึกโมเดล (Training set)
-   `test_images/` --- ชุดข้อมูลที่ใช้ตรวจสอบโมเดลระหว่างฝึก (Validation set
    ตามโค้ด)

ภายในแต่ละโฟลเดอร์ควรแยกภาพตามคลาส เช่น `bird/`, `cat/` และ `dog/`
เพื่อให้ระบบอ่านป้ายกำกับจากชื่อโฟลเดอร์ได้

-   **แหล่งที่มาดั้งเดิมของภาพ:** (https://www.kaggle.com/datasets/ashishpahal/animal-images-5-classes-bird-cat-dog-fish-rabbit/data)
-   **จำนวนภาพทั้งหมด:** 6000
-   **จำนวนภาพชุดฝึก:** 4800 `train_images/`
-   **จำนวนภาพชุดตรวจสอบ:** 1600 `test_images/`
-   **สัดส่วนการแบ่งข้อมูล:** train 80 test 20

หมายเหตุ: ไฟล์โค้ดที่ได้รับไม่ได้ระบุแหล่งที่มาดั้งเดิมหรือจำนวนภาพจริง และไม่มีชุด Test
แยกให้เห็น โดยโค้ดใช้ `test_images/` เป็นชุด Validation

### การเตรียมข้อมูล

-   ปรับขนาดภาพเป็น `224 × 224` พิกเซล
-   ปรับค่าสีให้อยู่ในช่วง `0–1` โดยหารด้วย `255`
-   ชุดฝึกเพิ่มความหลากหลายของภาพด้วยการหมุน ขยับภาพ และพลิกภาพในแนวนอน
-   ชุด Validation ปรับเฉพาะค่าสี ไม่ได้เพิ่มความหลากหลายของภาพ

## 3. แบบจำลองที่ใช้ ผลประเมินหลัก และข้อจำกัด

### แบบจำลองที่ใช้

ใน `models.py` มีแบบจำลอง

1. **Transfer Learning (MobileNetV2):** ใช้ MobileNetV2 ที่มีน้ำหนักเริ่มต้นจาก
    ImageNet โดยตัดชั้นจำแนกเดิมออก และเพิ่มชั้นสำหรับจำแนกสัตว์ 3 คลาส ได้แก่ Global
    Average Pooling, Dense, Dropout และ Softmax

ใน `train.py` โค้ดที่เปิดใช้งานสำหรับฝึกจริงคือ MobileNetV2 แบบ Transfer Learning

### ค่าตั้งต้นของการฝึก

-   ขนาดภาพ: `224 × 224`
-   Batch size: `32`
-   Epochs: `15`
-   จำนวนคลาส: `3`
-   Optimizer: Adam
-   Learning rate ของ Transfer Learning: `0.0001`
-   Loss function: `categorical_crossentropy`
-   Metric: `accuracy`

### ผลประเมินหลัก

ไฟล์ `evaluate.py` ใช้แสดงกราฟเปรียบเทียบผลระหว่างชุดฝึกและชุด Validation ได้แก่ -
**Accuracy:** Training Accuracy และ Validation Accuracy - **Loss:**
Training Loss และ Validation Loss

-   **Accuracy / Validation Accuracy :** 0.9792
-   **Loss / Validation Loss :** 0.0617

หมายเหตุ: ไฟล์ที่ได้รับยังไม่มีผลประเมินเป็นตัวเลข จึงไม่สามารถระบุค่าความแม่นยำจริงได้

### ข้อจำกัด

-   จำแนกได้เฉพาะนก แมว และสุนัข
-   ผลการทำนายขึ้นอยู่กับคุณภาพของภาพ แสง มุมมอง และความหลากหลายของข้อมูล
-   เว็บแอปต้องมีไฟล์ `model/transfer_model.h5` จึงจะเริ่มทำงานได้
-   จากโค้ดที่ให้มาไม่พบชุดทดสอบอิสระแยกจากชุด Validation
    จึงยังสรุปผลกับข้อมูลใหม่ทั้งหมดไม่ได้

| `train.py` | โหลดข้อมูล ฝึก MobileNetV2 บันทึกโมเดล และเรียกแสดงกราฟผลการฝึก |
| `evaluate.py` | วาดกราฟ Accuracy และ Loss ของชุดฝึกและชุด Validation |
| `requirements.txt` | ระบุแพ็กเกจที่ต้องติดตั้ง ได้แก่ TensorFlow, NumPy, Pillow, Gradio และ Matplotlib |
| `train_images/` | เก็บภาพสำหรับฝึกโมเดล โดยแยกโฟลเดอร์ตามคลาส (`bird/`, `cat/`, `dog/`) |

| `model/transfer_model.h5` | ไฟล์โมเดลที่ `train.py` บันทึก และ `app.py` โหลดมาใช้ทำนาย |
| `.venv/` | โฟลเดอร์สภาพแวดล้อมเสมือนของ Python แยกสำหรับติดตั้งแพ็กเกจ |
